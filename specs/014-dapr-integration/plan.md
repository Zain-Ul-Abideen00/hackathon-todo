# Implementation Plan: Dapr Integration & Event-Driven Architecture

**Branch**: `014-dapr-integration` | **Date**: 2026-02-07 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/014-dapr-integration/spec.md`

---

## Summary

Implement Dapr-based event-driven architecture by:
1. Deploying Strimzi Kafka cluster with 3 topics (`task-events`, `reminder-events`, `task-updates`)
2. Configuring 5 Dapr building blocks (pub/sub, state store, secrets, Jobs API, service invocation)
3. Adding EventPublisher class using **httpx HTTP API** (no dapr-client SDK needed)
4. Creating 4 consumer microservices: notification, recurring, audit, websocket
5. Using Jobs API for exact-time reminder scheduling (not cron polling)
6. Enabling Dapr sidecar injection with graceful shutdown in Helm charts

> **Updated**: Full SDD compliance per Hackathon II requirements. Using httpx HTTP API to Dapr sidecar (TaskAI pattern) - no external Kafka/Dapr libraries needed.

---

## Technical Context

**Language/Version**: Python 3.12 (backend), TypeScript (notification-service optional, but Python preferred)
**Primary Dependencies**: FastAPI, dapr-client, dapr-ext-fastapi, Strimzi, Kafka
**Storage**: PostgreSQL (existing), Kafka topics (new)
**Testing**: pytest (Python), httpx test client, manual `curl` to Dapr sidecar
**Target Platform**: Kubernetes (Minikube for local, Oracle OKE for production)
**Project Type**: Web application (monorepo with 5 microservices)
**Performance Goals**: Event publish < 2s latency, 100% event delivery (at-least-once)
**Constraints**: Fire-and-forget events, external notifications, httpx-only (no Kafka libs)
**Scale/Scope**: Single Kafka node (dev), 3 partitions per topic

> [!IMPORTANT]

> [!WARNING]
> **Strimzi Operator Dependency**: The Kafka cluster requires the Strimzi operator to be installed first. This is a one-time cluster-wide setup.

## Verification Plan

### Automated Tests

1. **Unit Tests (pytest)**
   ```bash
   cd todo-web-app/backend
   uv run pytest tests/test_events.py -v
   ```
   - Tests event model serialization
   - Tests publisher function (mocked DaprClient)

2. **Integration Tests (with Dapr)**
   ```bash
   cd todo-web-app/backend
   dapr run --app-id backend --app-port 8000 -- uv run pytest tests/test_events_integration.py -v
   ```
   - Requires Dapr sidecar running
   - Tests actual event publishing to local pub/sub

### Manual Verification

1. **Kafka Cluster Health**
   ```bash
   # Verify Strimzi operator is running
   kubectl get pods -n kafka

   # Check Kafka cluster status
   kubectl get kafka -n kafka

   # Verify topics were created
   kubectl get kafkatopics -n kafka
   ```

2. **Dapr Dashboard Verification**
   ```bash
   # Open Dapr dashboard
   dapr dashboard -k

   # Navigate to Components > taskpubsub
   # Verify status is "Running"
   ```

3. **End-to-End Event Flow**
   ```bash
   # 1. Port-forward backend
   kubectl port-forward svc/todo-backend 8000:8000 -n todo-app

   # 2. Create a task via API
   curl -X POST http://localhost:8000/api/tasks \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{"title": "Test Event Publishing"}'

   # 3. Check notification-service logs for received event
   kubectl logs -l app=notification-service -n todo-app --tail=50

   # Expected: Log entry showing "Received TaskCreatedEvent: ..."
   ```

4. **Scheduled Job Verification**
   ```bash
   # Wait 15 minutes or manually trigger
   dapr invoke --app-id backend --method /scheduler --verb POST

   # Check backend logs for reminder processing
   kubectl logs -l app=backend -n todo-app --tail=20 | grep "Reminder"
   ```
